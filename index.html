Part 1 · The problem

A genius with no memory is an expensive intern.

The "basic approach" is one chat window on one laptop. It works for a single question. It breaks the moment work spans days, projects or devices.

Basic approach
  • Starts every session from zero
  • You re-explain context, again and again
  • Knowledge trapped in one device's chat history
  • Research gets redone because nobody can find it
  • Stops working when the laptop sleeps
  • "Done" means "the AI said so"
What I run
  • Each session opens with a handover from the last
  • Decisions and open questions are tracked, by id
  • One memory, read by every device and agent
  • Research is written once, cited, and reused
  • An always-on cluster keeps it reachable
  • "Done" must ship the output that proves it
The system

Four parts, one job each.

🧭

The harness

The rulebook and guardrails every assistant loads on start: how to answer, what it may touch, when to stop and ask. Kept in version control, so every machine behaves the same way.

Value: consistent behaviour, not a new personality each morning.

📚

The knowledge base

A private wiki of what we have learned: full research reports with sources, plus short "rules of thumb" notes. An agent drafts; I approve before anything is published.

Value: pay for a piece of research once.

🗂️

Session management

Every working session is logged and summarised automatically. It ends with a short handover: where we are, what was agreed, what is waiting on me.

Value: pick up cold, in seconds, on any device.

📊

The portfolio

One registry of every project and its status, plus a single list of open questions, decisions, to-dos and ideas across all machines.

Value: nothing lives only in my head, or only in a chat.

The design rule underneath all four: plain text files in version control are the source of truth. No proprietary database, no vendor lock-in. If a tool disappears tomorrow, the memory is still readable by a human.
The picture

A working day

How a session actually runs.

It opens knowing where we left off

The last handover and the open-items count are loaded automatically. No "as I was saying last week".

We agree the objective

A few turns in, the assistant proposes what "done" looks like. I confirm. That is the boundary; it does not wander.

It checks what we already know

Before researching anything, it searches the knowledge base. New findings are written up with sources.

It delegates

A coordinator hands narrow jobs to specialist agents (research, spec, review) and keeps the conclusions.

Everything open gets an id

Questions, decisions, to-dos and ideas go into one list, visible from every device.

It writes the handover

Short, structured, and synced. The next session, on any machine, starts from it.

Why the hardware

Why Raspberry Pis, and why so many repos?

🍓

The Pis

Eight small computers in a rack, seven of them joined into one cluster (Docker Swarm). They sip power, they are mine, and if one dies the others carry on. They are the "always on" that a laptop cannot be.

🌿

The repos

Rules, knowledge and session records each live in their own private git repository. That gives full history, a copy on every machine, an off-site backup, and a clean answer to "who changed what, and when".

What that buys

A general assistant that lives on the cluster, reads the same memory I do, and answers from my phone at 2am or from a train, with no laptop or desktop left running at home.

Part 2 · Approach & security

Always reachable. Nothing exposed.

The obvious worry: "you put a computer with your memory on the internet?" No. The design goal is that nothing at home listens to the internet at all. Every connection is dialled out from inside.

Threat by threat

Each way in, and what closes it.

Scanning or attacking my home IP
Nothing answers. No port forwards; the tunnel dials out. DNS points at Cloudflare, so the home address is never published.
Someone finds the URL
Cloudflare Access demands an approved identity and a second factor at the edge. Unapproved traffic never reaches a Pi.
DNS spoofing or hijack
DNSSEC signs the records, so forged answers fail validation.
Eavesdropping in transit
TLS to the edge, and an encrypted tunnel from the edge to the cluster.
A stolen tunnel credential
Held as a Docker secret, rotatable, and the routes are managed centrally, so it can be revoked in one place.
One compromised service spreading
Segmented overlay network, per-host firewall, and data kept on a separate node from the apps.
The AI itself doing something silly, or being tricked by web content
OS-level sandbox, permission prompts, hooks that block actions, and a rule that I approve anything published to memory. Web content is treated as untrusted data.
Losing the data
Git. Every device carries a full copy with history, plus private remotes off-site.
Account takeover
Two-factor on the accounts that hold the keys: Claude, Cloudflare, GitHub, the domain registrar.
Engineer's honesty clause. No system has zero attack vectors, and I am not claiming one. What this design does is remove the whole class of "something at home is listening on the internet", and put a named control on every path that remains. The residual trust is in a handful of well-run providers (Anthropic, Cloudflare, GitHub, Tailscale) and in my own account hygiene.
